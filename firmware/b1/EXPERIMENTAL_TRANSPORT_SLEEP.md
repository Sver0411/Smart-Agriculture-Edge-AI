# Experimental E220 and Deep Sleep profiles

Build with ESP-IDF **v5.4.4**, target ESP32-S3. `lab` and `light-sleep` retain the original Wi-Fi/TCP path; `lora-prototype` enables the real B1 UART path; `deep-sleep-experimental` additionally enables the one-wake processing/snapshot/sleep task. Radio and Deep Sleep are disabled by default. Run `scripts/ci_build_b1.sh PROFILE /fresh/absolute/directory` for public compile verification.

Before flashing an E220 profile, supply the exact module model and commissioned settings. The current reference is E220-900T22D in transparent mode, 8N1, with RSSI trailer disabled. Set TX/RX/M0/M1/AUX pins, UART baud, AUX timeout, MTU and the exact 16-hex-digit readback of registers 00..07. CI values are illustrative public fixtures, not hardware commissioning values. Check board reserved/strapping pins and SHT30 SDA/SCL conflicts. The driver reads settings and refuses a mismatch; it does not rewrite RF channel/power configuration. No physical gateway or controller E220 endpoint is provided yet.

The 70-byte little-endian frame header, IDs, CRCs, limits, cross-layer ACK contracts and role routing are documented in [Phase 2](../../docs/research/PHASE2_LORA_DEVELOPMENT_REPORT.md). Local UART/AUX completion is not remote delivery. B1 retires reliable evidence only after the existing scoped gateway `PERSISTED_ACK`.

Deep Sleep requires E220 and excludes automatic light sleep. Configure the minimum sleep interval (default 60 seconds), communication window (default 10 seconds, plus finite driver initialization/shutdown timeouts) and maximum accepted elapsed-clock error. The task restores NVS HIGH before physical sampling, validates RTC, restores algorithms, reads SHT30, conditionally communicates, saves RTC, deletes I2C/UART drivers, holds M0/M1 in mode3 and arms a timer. Storage/snapshot/shutdown failure logs a conservative awake backoff; it does not erase HIGH.

`b1_deep_elapsed(identity, &elapsed_ms, &error_ms)` is a weak commissioning hook. Its default implementation returns false. A replacement must supply **measured elapsed time since the saved logical timestamp**, with a calibrated error bound. The planned sleep duration is not a measurement. Without that source, the task reports TIME_UNKNOWN, keeps sequence/owner/HIGH identity and safely rebuilds algorithm/report baselines. This may request an initial upload each wake. Full temporal continuity on a board remains pending.

All wakes use new boot IDs. Valid RTC wakes consume an identity-counter lease; cold/corrupt RTC startup reserves a new committed NVS range. Existing HIGH records retain their original IDs, become historical with UNKNOWN age, and a late ACK cannot advance the new-boot baseline. Snapshot version 1 contains the full SensorTrust/AdaptiveSense state and has a 6000-byte cap; actual encoding is 5070 bytes. Unknown schema/profile or CRC failures reject restoration; no algorithm-schema migration is silently attempted. Existing outbox NVS schema remains unchanged.

Read [Phase 3](../../docs/research/PHASE3_DEEPSLEEP_DEVELOPMENT_REPORT.md) and [integration evidence](../../docs/research/PHASE1_2_TO_PHASE3_INTEGRATION_REPORT.md) before board experiments. Compile/simulation success does not establish RF reliability, current reduction, battery lifetime, GPIO retention or actuator deployment. The firmware is a sensor endpoint and does not drive pumps, valves or fans.
